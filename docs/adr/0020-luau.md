# ADR 0020: Luau instead of Lua 5.4

- **Status:** Accepted
- **Date:** 2026-11-09
- **Follows:** ADR 0019 (direction); **supersedes** the language choice of ADR 0013

## Context

ADR 0019 makes Rolo an engine for people who learned on Roblox, and names
its scripting Lua-ux: Luau, unmodified, plus a measured performance layer.
Rolo's scripts ran on Lua 5.4.9 (ADR 0013). The stress test
(`examples/stress`) gave a baseline to compare against.

What has to stay true from ADR 0013: scripts are sandboxed (no files,
programs or native code), each file has its own globals, each object its
own `self`, a stuck script is stopped, memory is limited, errors name the
file and line, and nothing is compiled by the user.

## Decision

**Luau 0.744**, MIT, kept unmodified in `third_party/luau` (its parser,
compiler, bytecode and virtual machine; not type checking or native code),
built as `rolo_luau`. ScriptHost and ScriptApi move to its C API:

- **Loading:** `luau_compile` then `luau_load` with the file's
  environment. Syntax errors keep the "file:line: message" form.
- **Sandbox:** the base library (without `loadstring`, `getfenv`,
  `setfenv`), coroutine, table, string, math, utf8, bit32, buffer and
  vector. Never os or debug; Luau has no io or package. (Not the newer
  `class` and `integer` libraries either, until they settle.) `luaL_sandbox`
  makes the shared globals and libraries read-only: scripts cannot change
  `math` or `game` for each other. Each file's environment falls through
  to them and is marked *safe*, so Luau's fast paths for built-in functions
  stay on.
- **Stuck scripts:** Lua 5.4 counted instructions with a hook, which slows
  every script. Luau can be interrupted from another thread, so a watchdog
  thread checks four times a second whether one call has run longer than
  `GameSetup::scriptTimeLimit` (10 seconds), and only then asks Luau to
  stop it at its next safe point. Scripts that finish in time pay two
  stores per call. The limit is time, not instructions, so it also covers
  time spent inside Rolo's functions; it is generous so that slow
  computers and big set-ups (the stress test's spawner looks up 2000
  objects in its `start`) are not stopped.
- **Memory:** the allocator still enforces 256 MB. Luau allocates small
  objects in pages, so garbage is counted with its `onallocate` callback.
- **Errors:** Luau's errors are C++ exceptions of a type derived from
  `std::exception`; `guarded` lets them pass and converts only Rolo's own.
- **Numbers:** scripts have one number type (Luau's experimental 64-bit
  `integer` library is not opened), so a whole-number game variable is a
  number without a fraction; sound handles (up to 2³²) are passed as
  numbers.
- **Files:** `.luau` files are scripts as well as `.lua`.

Not done here, on purpose: native code (CodeGen, not allowed on iOS or
the web), and any change to Luau itself.

## Measurements

`examples/stress/README.md` has the tables. Interleaved runs on one
machine: code that runs in the language itself is about 2.3× faster
(`garbage`, `tidy`) and slow frames from garbage are halved; scripts that
mostly call Rolo's functions barely change, which points the next step at
the bindings. The first port made 48 bytes of garbage per script call
(the error handler was pushed anew); it was found by the stress test and
fixed.

## Consequences

- Scripts are Luau: types, `+=`, `continue`, string interpolation, `//`.
  Lua 5.4 extras are gone (`goto`, bitwise operators, `<const>`), numbers
  print without `.0`, and some error messages are worded differently. The
  scripting guide has a section for scripts written for 0.9.
- Rolo's own scripts (templates, examples) needed no changes.
- A thread per running game (the watchdog); joined when the game stops.
- `licenses/luau.txt` replaces `licenses/lua.txt` in every exported game.
- For the web build (ADR 0019), the watchdog needs threads; if they are
  not available there, an interrupt that checks the clock now and then
  is the fallback.
